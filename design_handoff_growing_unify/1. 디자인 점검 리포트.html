한눈에 보는 결론

나쁜 소식보다 좋은 소식이 큽니다 — 토대는 그대로 살아 있어요.

결론부터 — 브랜드와 디자인 토큰은 망가지지 않았습니다. 색(primary #1b4b36), 폰트(Outfit + Noto Sans KR), 반경·그림자 토큰, 그리고 사랑하셨던 .gd-* 카드 시스템이 지금도 index.css 안에 그대로 있습니다. 무너진 건 "스타일"이 아니라 일관성입니다. 기능을 빠르게 붙이면서 옛 디자인(레거시 클래스)과 새 디자인(.gd 리디자인)이 한 파일에 공존하게 됐고, 새 화면마다 자기만의 클래스·버튼·탭·모달을 새로 만들면서 "같은 일을 하는 UI가 화면마다 다르게 생긴" 상태가 됐습니다.

✓ 그대로 살릴 자산

01

두 세대의 CSS가 한 파일에 산다

망가진 느낌의 가장 큰 원인

레거시 + 리디자인 클래스 공존

심각

index.css가 179KB로 비대해진 핵심 이유입니다. 리디자인 때 도입한 .gd-* 블록은 파일 2,580번째 줄 부근부터 시작하는데, 그 앞쪽 2,500여 줄에 옛 디자인 클래스가 그대로 남아 있습니다. 새 화면들이 이 둘을 섞어 쓰면서 같은 요소가 화면마다 다른 출처의 스타일을 입습니다.

index.css — 같은 목적, 두 세대가 공존 /* 신세대 (리디자인, 2580줄~) — 살릴 것 */ .gd-card .gd-stat .gd-seg .gd-hero .at-row .pay-badge /* 구세대 (리디자인 이전, 그대로 잔존) — 정리 대상 */ .card .metric-card .makeup-summary-card .kakao-status .attendance-mobile-card .mobile-data-card .settings-tabs .dashboard-class-name .quick-att-student-name .tab-btn

증상: 카드 모서리·그림자·여백이 화면마다 미묘하게 다르고, 같은 "배지"가 어디선 .pay-badge, 어디선 .at-pill, 어디선 .kakao-status로 따로 정의됩니다.

02

같은 일을 하는 UI가 화면마다 다르게 생겼다

컴포넌트 어휘의 분열

탭·버튼·모달·인풋이 제각각

심각

새 기능이 각자 자기 CSS 네임스페이스(.mk-*, .dq-*, .kakao-*)를 만들면서, 동일한 역할의 컴포넌트가 3~6가지 버전으로 흩어졌습니다.

탭: .flow-tab.st-tab.settings-tabs / .kakao-tabs.tab-btn
버튼: .btn-primary.pay-btn.at-act.gd-copy.mk-btn.pay-icon
모달: .modal-content.mk-modal

가장 헷갈리는 사례 — 의미가 안 맞는 클래스 재사용: 보강·보충 화면(MakeupManager)이 날짜·학생·분량 입력에 전부 .msg-select(원래 "메시징 화면 셀렉트")를 씁니다. 이름과 용도가 어긋나 유지보수 때 혼선을 줍니다.

MakeupManager.tsx — 메시징용 클래스를 일반 폼에 차용 <input type="date" className="msg-select" .../> // 날짜인데 msg-select <select className="msg-select">... // 학생/반/분량 전부 동일
03

메뉴가 세 겹이고, 옛 메뉴 코드가 남아 있다

내비게이션 구조

3층 내비 + 데드코드

주의

현재 14개 탭이 5개 상단 메뉴(오늘·학생·수업·수납·소통) 아래 들어가 있고, 그 밑에 플로우 서브탭(.flow-tab)과 바로가기 칩(.flow-chip)이 또 깔립니다. 흐름을 살리려는 좋은 의도지만, 평가·통계·보강 같은 화면이 2~3단계 깊이에 묻혀 "지금 어디에 있는지" 감을 잡기 어렵습니다.

또한 App.tsx에 옛 메뉴 코드가 그대로 남아 있습니다 — 새 navigation.ts로 대체됐는데도 옛 NAV_GROUPS/TAB_TITLES가 void 처리되어 방치돼 있어요.

App.tsx — 죽은 코드 (제거 대상) const NAV_GROUPS = [...]; // 옛 3그룹 메뉴 NAV_GROUPS[1]?.items.splice(2, 0, ...); // 평가 끼워넣기 핵 void NAV_GROUPS; void TAB_TITLES; // 쓰이지 않음 = 데드코드

개선 방향은 섹션 IA에서 — 데스크톱은 한 화면에 다 보이는 그룹 사이드바로 펴고, 모바일만 5탭+더보기로 접습니다.

04

핸드오프 때 정한 인터랙션 원칙이 새 화면에서 깨졌다

상호작용 일관성

alert() 부활 · 모달 분열

주의

원래 핸드오프 원칙 4번은 "alert()/confirm() 대신 토스트 + 인라인 확인"이었습니다. 그런데 새로 들어온 보강·보충 화면은 검증 실패 시 브라우저 기본 alert()를 3곳에서 씁니다. 깔끔한 토스트 피드백과 톤이 어긋나죠.

MakeupManager.tsx — 원칙 이탈 alert('학생, 반, 날짜를 선택해 주세요.'); alert('이미 이 결석일에 연결된 보강 기록이 있습니다.'); // → .gd-toast + 인라인 에러로 통일해야 함

모달도 마찬가지 — 앱 전체는 .modal-content를 쓰는데 보강 화면만 자체 .mk-modal을 새로 그려, 모달 모서리·헤더·버튼이 미묘하게 다릅니다.

05

평가는 사실상 별도 앱 · 새 화면은 모바일 미정의

가장 큰 통합 부채

Exams 디자인 섬

심각

평가 관리(Exams.tsx)는 137KB 단일 컴포넌트에 전용 Exams.css(20KB)까지 따로 가진, 사실상 독립된 앱입니다. 외부 응시 라우트(#/exam/…)를 갖고, AI 비서 아이비도 이 탭에선 일부러 숨깁니다(activeTab !== 'exams'). 강력한 기능이지만 나머지 13화면과 비주얼 언어가 가장 동떨어져 있습니다.

새 화면의 모바일 부재

주의

원래 10화면은 @media(max-width:768px)에서 카드로 무너지도록 정성껏 설계됐습니다. 반면 데이터 점검(.dq-grid)·보강(.mk-cards)·카카오 등 새 화면은 모바일 분기가 일부만 정의돼, 좁은 화면에서 그리드가 깨지거나 가로 넘침이 생길 수 있습니다.

FIX

통일 시스템 — 한 어휘로 정리

"이 클래스 하나만 쓴다"는 정규 매핑

새 디자인을 만드는 게 아니라, 이미 좋은 .gd 시스템을 정본으로 삼고 흩어진 변형들을 거기에 흡수합니다. 아래가 "앞으로 이것만 쓴다" 표입니다.

역할지금 (분열)통일 (정본)
카드.card .metric-card .makeup-summary-card→.gd-card .gd-stat
탭.settings-tabs .kakao-tabs .tab-btn→.st-tab (상세) · .flow-tab (화면)
세그먼트.makeup-filter-tabs 등→.gd-seg / .gd-seg-b
버튼.pay-btn .at-act .mk-btn .btn-primary→.btn + .btn-primary/ghost/sm
상태 배지.pay-badge .at-pill .kakao-status→.pill + .ok/warn/danger/info
인풋.msg-select (의미불일치)→.field (input/select 공통)
모달.mk-modal→.modal-content
피드백alert() confirm()→.gd-toast + 인라인 에러
한 줄 핸드오프: "index.css에서 2580줄 위쪽(레거시)을 점진적으로 비우고, 모든 화면을 .gd 정본 클래스로 통일한다. 평가(Exams.css)는 .gd 토큰을 쓰도록 헤더·카드·버튼만 교체한다." — 색·로직·데이터는 손대지 않습니다.
FIX

새 메뉴 — 하루 흐름대로

데스크톱은 펼치고, 모바일은 접는다

원장님은 PC에서 하루 종일 쓰십니다. 그래서 모든 메뉴를 한 화면에 보여주는 그룹 사이드바가 5버튼+서브탭보다 빠릅니다. 메뉴를 하루 운영 → 원생·수업 → 기록·분석 3블록으로 묶어, 아침에 여는 순서대로 위에서 아래로 흐르게 했습니다.
